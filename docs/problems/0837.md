# 837. New 21 Game

[在 LeetCode 上查看](https://leetcode.com/problems/new-21-game/)

**難度:** 🟡 Medium　**標籤:** Dp Probability　**時間:** O(N)　**空間:** O(N)　**熟悉度:** 🔴 生疏

```cpp
/**
 * 題目：837. New 21 Game
 * 難度：中等 (Medium)
 * 描述：Alice 從 0 分開始，只要分數 < k 就持續抽牌，每次抽到 1 到
 * maxPts 之間任一整數的機率均等，加到分數上。求 Alice 最後分數 <= n
 * 的機率。
 *
 * 時間複雜度：O(N)
 * 空間複雜度：O(N)
 *
 * 解法思路：
 * （Probability DP + 滑動視窗優化，dp[i] 代表「在抽牌過程中，分數
 * 曾經恰好停在 i 分」的機率）：
 * 1. 特殊情況先處理：如果 k = 0，代表 Alice 一開始就不抽了（0 分
 *    <= n 一定成立），直接回傳 1.0；如果 n >= k + maxPts - 1，代表
 *    不管怎麼抽都不可能超過 n（抽到停止時最多也才 k-1+maxPts 分），
 *    直接回傳 1.0。
 * 2. dp[i] 代表「分數曾經恰好是 i」的機率。dp[0] = 1（一開始就是
 *    0 分）。狀態轉移：dp[i] = (dp[i-1] + dp[i-2] + ... + dp[i-maxPts])
 *    / maxPts，因為要湊出分數 i，一定是從 i-1 到 i-maxPts 之中某個
 *    分數，抽到對應點數湊過來的，每種來源機率均等。
 * 3. 直接算這個滑動視窗和每次都要 O(maxPts)，會變成 O(N*maxPts)；
 *    優化技巧是維護一個 windowSum，代表「目前視窗內 dp 值的總和」，
 *    每往前一步，視窗滑動一格：加入新進來的 dp[i]（如果 i < k，因為
 *    只有分數還沒到 k 的時候才會繼續抽牌、繼續累積機率），並扣掉
 *    滑出視窗的 dp[i-maxPts]（但只有 i-maxPts 對應的分數本身也 < k
 *    時才需要扣，因為 >= k 的分數不會再被拿來當「來源」延伸，Alice
 *    已經停止抽牌了）。
 * 4. 同時累加答案：只要分數 i 落在 [k, n] 這個範圍（代表停牌時分數
 *    合法、且沒超過 n），就把 dp[i] 累加進 result。
 * 5. 答案是 result，也就是所有「停牌時分數在 [k,n] 之間」的機率總和。
 */
class Solution {
public:
    double new21Game(int n, int k, int maxPts) {
        if (k == 0 || n >= k + maxPts - 1) return 1.0;
        vector<double> dp(n + 1, 0);
        dp[0] = 1.0;
        double windowSum = 1.0;
        double result = 0.0;
        for (int i = 1; i <= n; ++i) {
            dp[i] = windowSum / maxPts;
            if (i < k) windowSum += dp[i];
            else result += dp[i];
            if (i - maxPts >= 0 && i - maxPts < k) windowSum -= dp[i - maxPts];
        }
        return result;
    }
};
```
