# 1000. Minimum Cost to Merge Stones

[在 LeetCode 上查看](https://leetcode.com/problems/minimum-cost-to-merge-stones/)

**難度:** 🔴 Hard　**標籤:** Dp Interval　**時間:** O(N³ / K)　**空間:** O(N²)　**熟悉度:** 🔴 生疏

```cpp
/**
 * 題目：1000. Minimum Cost to Merge Stones
 * 難度：困難 (Hard)
 * 描述：給定 n 堆石頭排成一列，stones[i] 是第 i 堆的石頭數。每次可以把
 * 「連續的 K 堆」合併成一堆，成本是這 K 堆的石頭總數。求把所有石頭合併
 * 成一堆的最小總成本；如果不可能合併成一堆，回傳 -1。
 *
 * 時間複雜度：O(N³ / K)
 * 空間複雜度：O(N²)
 *
 * 解法思路：
 * （Interval DP，這題是同分類裡最難的一題，多了「每次固定合併 K 堆」的
 * 限制，狀態轉移要多考慮這個限制）：
 * 1. 先判斷可不可能：每次合併會讓堆數減少 K-1（K 堆變 1 堆），所以要把
 *    n 堆變成 1 堆，(n-1) 必須是 (K-1) 的倍數，否則永遠合併不完，
 *    直接回傳 -1。
 * 2. dp[i][j] 代表「把 stones[i..j] 這段合併到不能再合併為止（合併到
 *    剩下最少堆數，但不一定是 1 堆）」所需的最小成本。
 * 3. 狀態轉移，枚舉切割點 mid（每次跳 K-1，因為切出來的左半段長度必須
 *    能被完整合併，長度要滿足 (len-1) % (K-1) == 0）：
 *    dp[i][j] = min over mid of dp[i][mid] + dp[mid+1][j]。
 * 4. 關鍵的最後一步：如果這個區間的長度剛好也滿足「可以合併成剛好 1 堆」
 *    的條件（(len-1) % (K-1) == 0），代表這個區間目前已經被拆成剛好 K
 *    個更小的、各自合併到底的區塊，可以再花一次「合併這 K 堆」的成本，
 *    所以要再加上這個區間的石頭總和（用前綴和快速查詢）。
 * 5. 按照區間長度由小到大遞推（長度從 K 開始，因為至少要 K 堆才能觸發
 *    一次合併），答案是 dp[0][n-1]。
 */
class Solution {
public:
    int mergeStones(vector<int>& stones, int K) {
        int n = stones.size();
        if ((n - 1) % (K - 1) != 0) return -1;
        vector<int> prefix(n + 1, 0);
        for (int i = 0; i < n; i++) prefix[i + 1] = prefix[i] + stones[i];
        vector<vector<int>> dp(n, vector<int>(n, 0));
        for (int len = K; len <= n; len++) {
            for (int i = 0; i + len - 1 < n; i++) {
                int j = i + len - 1;
                dp[i][j] = INT_MAX;
                for (int mid = i; mid < j; mid += K - 1) {
                    dp[i][j] = min(dp[i][j], dp[i][mid] + dp[mid + 1][j]);
                }
                if ((len - 1) % (K - 1) == 0) {
                    dp[i][j] += prefix[j + 1] - prefix[i];
                }
            }
        }
        return dp[0][n - 1];
    }
};
```
