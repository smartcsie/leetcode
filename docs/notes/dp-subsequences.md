# DP on Subsequences 筆記

**核心特徵**：這個分類的共同點是「子序列」本身的計數或最佳化，但
跟 `dp-lcs`（兩個序列互相配對）不同，這裡通常只有**一個**序列，
要對它的所有子序列做某種統計。

| # | 題目 | 求什麼 | 關鍵技巧 |
|---|---|---|---|
| 446 | Arithmetic Slices II - Subsequence | 等差子序列個數 | 每個位置維護「公差->數量」的 map |
| 940 | Distinct Subsequences II | 不同子序列總數 | `dp = 2*dp - last[c]` 去重公式 |
| 1425 | Constrained Subsequence Sum | 有距離限制的最大子序列和 | 單調隊列優化滑動視窗最大值 |
| 1987 | Number of Unique Good Subsequences | 不同「無前導零」二進位子序列數 | 分開追蹤「以0結尾」「以1結尾」的數量 |

## 容易搞混的地方

- **940 的去重公式是這個分類最經典的技巧**：`dp = 2*dp - last[c]`——
  每加入一個字元，子序列數量理論上會翻倍（每個舊子序列都能接上這個
  新字元），但如果這個字元之前出現過，會產生重複，要扣掉「上次看到
  這個字元時」的 dp 值。
- **446 要用 map 不能用普通陣列**：因為公差可以是任意整數（包含
  負數），沒辦法像一般 DP 那樣用陣列索引，只能用雜湊表存「公差 ->
  數量」。
- **446 的「+1 但不算進答案」細節**：長度 2 的候選（單純一對數字）
  不算等差子序列（題目要求長度至少 3），但要記錄下來以便之後接上
  第三個元素時能被使用，這個「記錄但不計分」的細節容易漏掉。
- **1425 需要單調隊列，不是單純的 DP 遞推**：因為要在「最近 k 個」
  dp 值裡找最大值，如果每次都重新掃描 k 個會變成 O(N*K)，要用
  單調遞減佇列把查詢降到攤還 O(1)——跟 1696 Jump Game VI 是完全
  同一個模板。
- **1987 的「+1」特例**：一般轉移規則會排除「0 自己開頭」的情況
  （避免前導零），但單獨的 "0" 這個子序列本身是合法的好子序列，
  需要在最後額外加 1（只有字串裡真的出現過 '0' 才加）。
