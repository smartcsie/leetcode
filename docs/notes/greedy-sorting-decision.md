# Sorting + Greedy Decision 筆記

**核心套路**：先用某個關鍵依據把資料排序，排序完之後，答案就能用簡單的
貪心規則（直接掃描、雙指標、或依序分組）算出來——**排序本身消除了
「要考慮所有排列組合」的複雜度**，把問題降階成線性掃描。

判斷這題屬不屬於這個 pattern 的關顐：**排序的依據是什麼、排序完之後
用什麼邏輯做決策**，這兩件事決定了題目的難度跟解法的走向。

| # | 題目 | 排序依據 | 排序後的貪心邏輯 |
|---|---|---|---|
| 406 | Queue Reconstruction by Height | 身高由高到低；同身高 k 值由小到大 | 依序插入到陣列第 k 個位置 |
| 881 | Boats to Save People | 體重由小到大 | 雙指標夾：最輕 + 最重湊一艘船 |
| 1029 | Two City Scheduling | costA - costB 由小到大 | 前一半去 A 市，後一半去 B 市 |
| 1710 | Maximum Units on a Truck | 每箱單位數由多到少 | 依序裝，優先塞單位密度高的箱子 |
| 945 | Minimum Increment to Make Array Unique | 數值由小到大 | 掃描時發現重複就往上補到 `prev+1` |
| 2966 | Divide Array Into Arrays With Max Difference | 數值由小到大 | 每 3 個連續分一組，檢查組內最大差 |
| 3011 | Find if Array Can Be Sorted | 保持原順序，但只允許同「二進位 1 的個數」的元素互換 | 逐段（相同 popcount 為一段）各自排序，檢查整體是否變成非遞減 |
| 3684 | Maximize Sum of At Most K Distinct Elements | 數值由大到小（先去重） | 依序取前 k 個 |

## 常見的排序依據分類

- **單一數值排序**（881、1710、945、2966、3684）：直接照一個欄位排序，
  排序後用線性掃描或雙指標處理。
- **複合鍵排序**（406）：排序依據不只一個欄位，且欄位之間的排序方向
  可能相反（身高降冪、k 值升冪），這種題目通常需要想清楚「為什麼
  要先處理某個屬性，才能讓後面的插入/決策不會被破壞」。
- **衍生值排序**（1029）：排序的不是原始資料本身，而是從原始資料算
  出來的一個新指標（`costA - costB`），這種題目的關鍵是想出「排序
  哪個衍生值，才能讓貪心決策成立」。
- **分組限制排序**（3011）：不是整個陣列一起排序，而是先分組（依某個
  不變的屬性分組），每組內部才能排序，這種題目要先想清楚「哪些元素
  之間可以互相交換」。

## 容易搞混的地方

- **406 的排序方向很反直覺**：身高高的先處理、身高相同時 k 值小的
  先處理——這個順序選擇本身就是解題的關鍵洞察，不是隨便選的。
- **1029 排序的是「差值」不是原始數字**：容易誤以為要照 costA 或
  costB 單獨排序，但正確做法是排序兩者的差，這樣才能同時兼顧「這個
  人該去哪個城市」跟「維持左右兩邊人數相等」兩個限制。
- **跟 `greedy-priority-queue` 的區別**：這個分類是「一次排序、一次
  掃描」就結束；如果題目需要「排序後還要動態維護一個會變化的候選集
  合」（例如每次取完最大值後，候選池會更新），那屬於
  `greedy-priority-queue`，不是這個分類。
